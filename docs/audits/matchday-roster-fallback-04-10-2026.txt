Football Player V1: local Match Day participant fallback candidate
04:10:2026. Local review only, separate from Fans clock/notification/release work.

Request
If the Coach forgets to configure the match squad, an authorised scorer should
choose active players in that exact Team, including Trial players, for goals,
assists, cards and substitutions. Selected participants retain player IDs so
names shared by two players do not cause incorrect statistics credit.

Conservative policy
The server enables fallback only when BOTH:
 - no match_day_player_squad_decisions row exists for the fixture; and
 - no squad/selection/removal event log or event_player_removal_commands record
   exists for the fixture.
Every decision row, including waiting or undecided, disables fallback. These
states cannot safely be interpreted as forgotten configuration. Explicit selected
rows remain authoritative; not_selected/withdrawn players do not become eligible.
If a once-configured squad is later emptied, its history disables fallback.
This deliberately covers fewer empty-squad cases than an empty-array heuristic.
No automatic selection, availability, invitation or notification is performed.
Deleting decision rows AND their audit history administratively would lose that
distinction; no such mutation or history inference is part of this candidate.

Eligibility and privacy
The shared private relation requires the fixture's exact club AND team, active
status, archived_at null, a nonblank name and section Squad or Trial. Trial
requires the existing club trialPlayers plan capability. Missing players,
transferred players, inactive/archived players and other sections are excluded.
Roster reads require authenticated exact-match current-day staff or the current
selected Parent scorer, an active same-club/team link, the existing scorer
authority/handover check, and an available unconcluded fixture. The getter also
enforces existing fixtures and players plan capabilities. Ordinary Parent, Fan,
Player and guest requests cannot use the new RPC. Existing guest flow is
unchanged. No player-table or other-team RLS access is widened.
Only ID, player name, shirt number and team ID are returned for participants;
minimal event ID/link/version data is included under the same scorer/staff scope
so existing event response builders cannot drop identities. Match/team envelope
validation remains in the clients. Failed or malformed loads throw; an empty
verified result does not trigger a local roster fallback. Existing previously
verified offline data retains the IDs, subject to server validation on reconnect.

Local implementation
New read RPC: get_match_day_event_participants(uuid,uuid).
New goal RPC: record_match_day_goal_v4, validates IDs and canonicalises names
from that exact eligible roster before using the existing score writer.
New card/substitution RPC: record_match_day_scorer_event_v2, retains actor,
lifecycle, idempotency and Coach-only match-participant checks, using IDs and the
same eligible relation for linked players.
New Parent journal RPC: apply_parent_match_day_command_v2, retains existing
capture/revision/idempotency checks and notification journal handling. New
participant payloads use this version; older queued payloads use the old API.
New Coach journal RPC: apply_coach_match_day_command_v2, keeps the existing
Coach/team permission, capture, revision, chaining and replay constraints while
dispatching participant actions to the same identity-aware goal/event writers.
Coach/Parent read paths load the scoped roster, and pickers store participant
IDs. Manual edits clear stale IDs; same-name substitutions are allowed when
the actual IDs differ. Opponent/Other participants do not acquire Team IDs.

Proposed local migration adds scorer_player_id, assist_player_id and
participant_identity_version to match_day_events, with player foreign keys.
get_end_season_stats and app_private.end_season_stats_range prefer IDs for new
events, retain historical name matching only for legacy identity-version-null
events, and include entitled active Trial players in the scoped totals.
New unlinked Other goal names do not receive automatic player-stat credit.
Own goals and voided events retain the existing exclusion rules. The server
checks IDs again at write time, so roster snapshots cannot authorise stale IDs.
Parent and Coach correction forms now retain IDs, resolve a linked person's
current name after a rename, support explicit re-selection (including duplicate
names) and allow clearing a link. Parent manual text edits clear its ID; Coach
linked fields require a unique current choice before retaining an ID. Linked
correction names/shirts must exactly match the current eligible server person;
mismatches are rejected before the original score/audit writer executes.
New RPCs correct_match_day_goal_v3 and correct_coach_match_day_goal_v2 retain
original authority and score/audit handling, and record before/after IDs. Coach
lost-response reconciliation checks IDs, so duplicate names cannot mask failure.
Correcting an old name-only event does not infer an ID. Explicit re-selection
links it; deliberately unlinked text gets identity version 1 and no name credit.
Old correction calls clear unchanged IDs after name, shirt, side or own-goal
changes, retaining identity version to prevent accidental name-only credit.
Saved Coach card/substitution corrections clear IDs when changing participant
type, and re-selection uses the shared roster and the existing outbox repair.
Both stats APIs now count corrected as well as active goals. Tests reproduced
the inherited active-only exclusion, then verified identity swaps, clearing,
own-goal reversal, removal/replay and player deletion remove/restore only the
correct credit. No historical event backfill is performed.
Old clients/old RPCs retain their existing selected-squad/name behaviour. This
candidate does not silently enable fallback in the old Guest or web scorers.
